# 数据安全

## 数据边界
- 业务资料默认在本机解析，不上传到知识库以外的位置。
- 调用远程 Provider 时，用户提交给模型的文本可能离开本机；企业部署应使用批准的内网模型服务。
- 审核历史只保存结构化结果、文件元数据和受控路径，不保存大型二进制。
- 删除历史记录默认不删除原始业务文件。

## 发布检查
- 扫描 API Key、Token、密码和私钥。
- 扫描开发机用户名、盘符绝对路径和临时目录。
- 排除真实井名、真实合同、标书及其他敏感业务样本。
- 测试样例必须人工构造或完成脱敏。
- 检查导出目录、日志、缓存和测试临时文件未进入版本控制。

## 企业终端安全审查
- 正式 Windows 安装包、主程序和 Sidecar 必须使用同一企业认可的代码签名证书；正式发布缺少签名配置时应直接失败。
- 由信息安全部门按发布者证书建立 App Control for Business 或 Defender 允许策略。不要为整个安装目录、用户目录或知识库设置杀毒排除。
- 首次部署先进入 App Control、ASR 和 EDR 审计模式，覆盖安装、启动、模型调用、文档处理、语音、更新、卸载等路径，再逐步切换到强制模式。
- 每个版本保存安装包 SHA-256、签名验证结果、依赖清单、联网域名清单、变更记录和扫描报告，作为审批和事件追溯依据。
- 企业托管策略默认只允许随包技能和内置插件；项目、用户、远程技能及 npm/file 插件必须由管理员显式批准。
- 离线环境关闭自动更新和外网 Provider；联网环境只允许批准的内网模型、更新源及连接器域名。
- 打包资源启动时校验文件清单与 SHA-256，Electron 只从已校验的 ASAR 加载应用代码，并关闭生产环境不需要的 Node/调试入口。

误报应向终端安全平台和安全厂商提交样本复核，并保留检测名称、规则、文件 Hash、签名链和版本号。不要通过改名、加壳、混淆、关闭 EDR 或动态下载可执行文件规避检测。

## 知识引用
知识检索只返回当前生效版本。每个命中包含资料编号、版本、章节或段落、来源路径、摘录和更新时间。未命中可靠来源时必须明确提示人工复核，不得编造标准编号。
