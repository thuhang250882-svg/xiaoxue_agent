# 指定录井目录的 MDB 基础数据审核接入

## 已实现

`geology_report_review` 新增 `directory` 和 `mdbFile` 参数，可在审核报告时直接读取用户明确指定目录内的 MDB。用户无需预先转换成 Excel。

示例请求：

> 审核录井目录“C:\Users\Administrator\Desktop\哨东103井”，主报告是“哨东103井录井报告.docx”，用“哨东103地质录井.mdb”核对报告基础数据。

对应工具参数：

```json
{
  "directory": "C:\\Users\\Administrator\\Desktop\\哨东103井",
  "primaryReport": "哨东103井录井报告.docx",
  "mdbFile": "哨东103地质录井.mdb"
}
```

可通过 `filenames` 选择同目录附表。已有本轮上传附件时使用上传附件作为报告来源，目录提供 MDB；无上传附件时读取目录中的主报告及明确选择的附表。目录中只有一个主报告、一个 MDB 时可自动选择；多版本必须明确选择，不按时间、文件排序或邻井名称猜测。

## 数据与读取边界

- 当前只读取指定目录第一层；不会递归混入邻井资料。
- 目录必须出现在本会话用户的非合成文本中，并经过工具的读取权限检查。附件提取文本、工具输出和模型推测不能提供目录授权。
- 文件必须位于解析后的授权目录内，拒绝指向目录外的链接、相对路径越界和任意 SQL。
- Windows 后台启动 32 位 PowerShell，使用本机 Jet 4.0 驱动，只在临时 MDB 副本上查询。脚本内嵌进服务端，不依赖桌面的独立导出脚本。
- 单 MDB 上限 512 MiB、读取器 120 秒期限；标准录井表单表最多 10,000 行、合计最多 50,000 行、审核快照最多 64 MB。缺少驱动、加密/不兼容文件或超过限制时明确报错，不降级成“数据库审核通过”。
- 统计全部用户表名、字段和行数；实际加载 AJLJ/ADLJ 标准录井表的原始记录用于数据质量检查，其他扩展表保留结构和行数清单。
- 报告副本复用会话附件存储。读取结束清除临时 MDB；原始数据库不改写。

## 本轮自动核验范围

依据用户提供的 `Q/SY XJ 0222-2009《录井数据库逻辑结构》`（PDF 正文标注“2014年11月确认”），适配标准 `AJLJ01`，并兼容实际数据库使用的 `ADLJ01` 表名前缀：

| 报告字段 | MDB 字段 |
| --- | --- |
| 井号 | JH |
| 井别 | JB |
| 完钻井深 | WZJS |
| 完钻垂深 | WZCS |
| 补心高 | BXG |
| 开钻日期 | KZRQ |
| 完钻日期 | WZRQ |
| 完井日期 | WJRQ |
| 完钻层位 | WZCW |
| 完井方法/方式 | WJFF |

上述字段除 `JB` 外均来自标准表1，深度单位按标准规定为米；`JB` 是当前实库扩展字段，结果会明确区分。标准正文版本按 PDF 内页识别，不把文件名中的“2023”作为标准版本。

优先以含“井号”和其他基础字段的报告基础表定位本井，不把邻井对比表中的井号当成本井。MDB 必须只有一条对应井号记录，否则停止字段比较并列出无法核验项。

开钻、完钻、完井日期分别核对，不混用；比较到日。报告数值须有明确单位，支持 m/米和 km 的显式换算，绝对容差 0.005m。设计井深不作完钻井深，缺失值、负深度和无单位值不判为一致。层位代号按文字比对，不擅自推断代号与中文层位等价。

数据质量轨道还检查39张标准表的结构覆盖、标准关键字段、井号归属、开钻/完钻/完井日期顺序、完钻井深和补心高范围、完钻垂深关系，以及含 `DJSD1/DJSD2` 表的顶底深度顺序。跨表专业语义、规范值代码表和最终解释结论仍需人工复核，不能宣称“整库与整份报告全部审核完成”。

## 审核输出

工具返回 `qualityTracks`，独立记录报告质量审核岗和数据质量审核岗的状态、范围及问题数。有 MDB 时两个轨道都执行；无 MDB 时报告质量继续执行，数据质量明确标记“未执行”，不会把缺少 MDB 当作报告缺陷。

`mdbAudit` 逐项包含报告原值及表格行列、数据库原值及表/记录/字段位置、状态和原因。状态分为“一致”“差异待复核”“无法核验”；数据质量问题保存在独立的 `mdbAudit.dataQuality.issues`，不会混入报告质量问题数。

差异和覆盖范围写入最终 `ReviewResult.issues`，随现有审核意见导出流程进入报告；业务任务结果保存 `mdbAudit`，来源记录保存 MDB 大小和 SHA-256。不会自动认定数据库一定正确，也不会自动修改报告或数据库。
