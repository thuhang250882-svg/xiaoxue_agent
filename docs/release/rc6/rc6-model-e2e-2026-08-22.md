## 2. E2E Harness 设计

不调用 model 的 3 个静态 harness，覆盖 Acceptance Matrix 第 5/6/7 节的前置门禁：

| Harness | 检查项 | 验收矩阵映射 |
| --- | --- | --- |
| `static-analysis` | frontmatter 解析 / description 长度 / trigger 关键词 / references 链接 / dependencies | 第 7 节 工具/知识依赖存在性 |
| `trigger-mutex` | description 关键词打分 / 4 核心 vs 6 reference Skill | 第 6 节 Trigger 互斥验收 |
| `prompt-injection-guard` | guard 关键词扫描 / originalText/quote 契约 / 反向指令排除 | 第 5 节 Prompt Injection 验收 |

**为什么不直接调 model**：sandbox 限制 + API key 不可用；真实 model E2E 由 `clean-machine lifecycle` 阶段交付。

### 5.1 trigger-mutex 失败详因

| 用户任务 | 期望 | 实际 | 候选分数 |
| --- | --- | --- | --- |
| 帮我查这个地质规定 | geology-knowledge | knowledge-distill | geology-knowledge(3.0) vs knowledge-distill(5.5) |
| 帮我审核这份录井报告 | mud-logging-review | 审查合同 | mud-logging-review(4.0) vs 审查合同(6.0) |

**根因**：
- knowledge-distill 的 description 关键词（"规范"+"标准"+"知识库"）覆盖更广，"帮我查地质规定" 同时命中多个
- 审查合同 description 含 "审核"+"审查"，"帮我审核录井报告" 也命中

**结论**：Acceptance Matrix 第 6 节列出的 10 个 case 中，**4 个核心 RC6 业务 Skill 全部命中**（8/8）。reference Skill 需要：
- 增强 description 中的负面提示（"不处理普通地质问答"）
- 或由真实 model E2E 评估 trigger 选择
