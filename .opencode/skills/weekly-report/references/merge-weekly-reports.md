# 院级汇总件（多单位材料合并）

**触发**：用户提供一批基层单位周报，要求“收集之后合到一个文档里”“汇总总结到整个公司的材料中”或“按汇总的周工作联席会格式排版”。

**产出**：一份全新命名的院级汇总 DOCX，版式沿用 `formats/02-联席会汇报.md`，结构为公司四大块、需要协调的问题和单位分节。不得覆盖任何已有文件。

## 一、成稿结构（固定）

```text
地质研究院（录井工程分公司）
周工作联席会汇报
一、上周工作联席会议安排的各项工作落实情况
二、生产、经营情况
    （一）工作量完成情况
    （二）设备状态及动用情况
    （三）人员情况
    （四）经营情况
三、双周完成的主要工作
四、本周主要工作安排
五、需要公司协调的问题
六、分单位材料
    各项目经理部／分院／中心／科室
```

单位分节内部固定五块：上周联席会议安排事项落实情况 → 生产、经营情况（工作量／设备／人员／经营）→ 双周完成的主要工作 → 需要协调的问题 → 本周主要工作安排。某块内容少就写 `无。`，不要跳过。

## 二、执行顺序

1. **清点源件**：列出范围内全部 `.doc` / `.docx`，排除输出目录、临时文件和目标文件；记录源文件清单，全程只读。
2. **抽取内容**：优先使用小雪内置文档读取能力读取源件。内置 `document_engine` 可读取旧版 `.doc`，不需要外部转换器。对本地 `.docx` 也可运行：

   ```text
   <xiaoxue-python> scripts/merge_builder.py --extract <源件1.docx> <源件2.docx> --json-out <新的提取结果.json>
   ```

   `--extract` 只支持 `.docx`；旧版 `.doc` 必须走小雪内置文档读取能力。提取结果 JSON 也必须使用不存在的新路径。
3. **归类核对**：以正文中的单位名为准。先把各单位同类事实拉平为工作量、设备、人员、经营等院级内容，再把单位原文按五块压缩到第六部分。数字、单位、状态和来源不得推算；未报写“未报”。
4. **准备标记文本**：普通正文直接写；`#0` 为大标题或单位名，`#1` 为一级标题，`#2` 为二级标题。表格依次写 `%T` 第一行表头、`%H` 第二行表头、可选 `%W` 列宽权重、一个或多个 `%R` 数据行、`%E` 结束。字段用中文分号分隔；`^N` 横向跨 N 列，`^V` 为纵向合并起点，`~` 承接上方单元格。
5. **生成新文件**：

   ```text
   <xiaoxue-python> scripts/merge_builder.py <内容.txt> <新的院级汇总.docx>
   ```

   目标存在时生成器会拒绝写入。改用带时间戳或递增序号的新文件名，不得删除、替换或覆盖旧文件。
6. **回读验证**：用 `office_artifact_preview` 或等价的本地预览能力打开新文件，核对 A4 页面、页边距、32/28 磅固定行距、字体、编号、两行表头、全线框和列宽。预览或回读失败时不得宣称完成。

## 三、已知风险与处理

| 风险 | 处理 |
|---|---|
| 旧版 `.doc` 不能由 python-docx 读取 | 使用小雪内置 `document_engine` 读取，不调用外部或云端转换器 |
| 历史汇总件使用默认边距或单倍行距 | 以本技能固定版式重建，不照抄历史汇总件样式 |
| 单行表头放不下分组 | 使用 `%T` + `%H` 两行合并表头 |
| 单位原文形成整页大段 | 生成器按句号拆分，超过 320 字再按分号拆分 |
| 文件名不能可靠表示单位 | 以文档正文中的单位名称为准 |

## 四、绝不做什么

1. 不改写、不移动、不覆盖基层单位原始件。
2. 不覆盖任何既有汇总件；始终生成新文件。
3. 不编造单位未报数字，不把缺报推算为零。
4. 不把内部材料上传到云端，不调用 WorkBuddy 专用编辑器或实例池接口。
