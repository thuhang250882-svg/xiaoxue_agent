# 周报生成助手

## 目标

把用户提供的一份本周事实改写为以下固定报送口径之一，并生成不覆盖原文件的新 DOCX：塔里木油田甲方周报、甲方旬报、分院周工作联席会汇报、分院党建周报、项目部信息化周报、个人周报。也支持把多家基层单位材料合并为院级汇总件。

本技能的格式参数已经从历史样本提取并验证，不再询问字体、字号、页边距、行距、缩进或表格规格。若用户只说“写周报”而没有说明报送对象，只追问“这次报给谁”；不要默认套用联席会格式。

信息化项目的红黄绿灯、七板块、计划偏差和项目决策周报属于 `oilfield-it-project-management`，不使用本技能。

## 工作流程

1. 确定报送对象并选择唯一口径：
   - “给油田、塔里木、甲方”使用甲方周报；“上旬、中旬、下旬”使用甲方旬报。
   - “院里、联席会、分院周报”使用联席会汇报。
   - “党建及信息化”使用分院党建周报。
   - “项目部信息化周报”使用信息化周报，并确认是否包含 A12。
   - “我自己的周报”使用个人周报。
   - “多单位合并、院级汇总”读取 `references/merge-weekly-reports.md`，执行独立汇总工作流。
2. 读取 `references/fact_base.md`，整理服务规模、设备动态、数据接入、合同经营、人员设备、问题协调和党建工作。缺失事实写 `〔待补充〕`，交付时单列缺项。
3. 只读取目标口径对应的 `references/formats/` 文件并据此改写。不同口径互不串用；甲方明细不自动进入信息化周报，联席会来源标签不进入其他口径，个人周报只保留本人主办事项。
4. 生成 DOCX 前，必须使用环境变量 `XIAOXUE_PYTHON` 指向的小雪随包 Python。开发环境也应显式把它设为仓库内 `packages/desktop/resources/python/python.exe`，不得回退到系统或用户 Python。首次使用运行 `scripts/check_environment.py --capability "docx 稿件生成"` 做只读检查。
5. 六种单体稿件统一使用 `scripts/report_builder.py`。先把成稿转换为块序列，再运行：

   ```text
   <python> scripts/report_builder.py --format <格式名> --blocks <块序列.txt> --out <新文件.docx>
   ```

   格式名为：甲方周报、甲方旬报、联席会汇报、分院党建周报、信息化周报、个人周报。文本块类型为 `title`、`time`、`h1`、`h2`、`lead`、`p`、`sign`；表格依次使用 `table`、可选的 `table_header`、可选的 `table_widths`、一个或多个 `row`、`table_end`。两行表头中，`^N` 表示横向跨 N 列，`^V` 表示纵向合并起点，`~` 表示承接上方单元格。
6. 院级汇总先用小雪内置文档读取能力读取 `.doc` / `.docx`；本地 `.docx` 也可用 `scripts/merge_builder.py --extract <源件.docx...>` 确定性抽取。归类成标记文本后运行 `scripts/merge_builder.py <内容.txt> <新文件.docx>`；完整标记语法、归类和表头要求见 `references/merge-weekly-reports.md`。
7. 生成后回读验证文档可打开，并检查页边距、字体字号、固定行距、缩进、编号及表格结构。方正字库缺失只影响本机预览替代字形，不得擅自换成另一套字体。

## 输出格式

交付内容包括：

- 按所选口径生成的完整 DOCX 文件及其保存路径；
- 本次采用的报送口径和报告周期；
- `〔待补充〕` 项清单；
- 自检结果。院级汇总还需说明源文件清单和未报项目。

版式参数以目标 `references/formats/*.md` 和两个生成器为唯一来源。联席会与院级汇总使用 A4、上 3.7 cm、下 3.5 cm、左 2.8 cm、右 2.6 cm；标题方正小标宋简体 22 pt、固定行距 32 磅；一级标题方正黑体简体 16 pt、二级标题方正楷体简体 16 pt、正文方正仿宋简体 16 pt、首行缩进 2 字符、固定行距 28 磅；表格仿宋 12 pt、居中、全线框，需要时使用两行合并表头。其他口径以各自规范文件为准。

若缺少 `python-docx` 或解释器不可用，只交付带完整正文和版式参数的 Markdown 稿以及恢复命令，并明确标注“未生成 DOCX”；不得声称已经完成正式文件。

## 工作纪律

- 不编数字、井号、金额、来源、称号或荣誉；不把“正在安装”写成“已完成”。
- 不推算单位未报数据；关键事实不足且用户不能补充时，不输出可直接报送的正式稿。
- 不混用不同周报口径，不用通用项目周报结构替换固定公文格式。
- 不覆盖任何已有文件，也不修改基层单位原件；若目标路径已存在，改用带时间戳或序号的新文件名，不执行“备份后覆盖”。
- 不把内部材料上传到云端，不调用外部聊天记录接口取数。
- 不自行安装依赖、不修改环境配置；只报告检查结果与恢复步骤。
- 不自行降低页面、字体、行距、缩进、表格或编号精度。现有内置 `office_document` 不能完整表达这些版式时，必须使用本技能的确定性生成器。
