# 技术选型评审

## 概述

本技能为西部钻探地质研究院巴州分公司的信息化项目提供结构化的技术评审与选型支持。评审场景覆盖 IT 项目全生命周期的三个关键决策节点：

| 评审类型 | 适用场景 | 典型用例 |
|----------|----------|----------|
| **技术方案评审** | 评估某一技术方案的可行性和完整性 | AI智能录井系统设计方案评审、井场网络架构方案论证 |
| **供应商选型** | 在多家候选供应商之间比较和选择 | 3家井场视频监控方案比选、GPU服务器供应商选型 |
| **系统验收** | 交付系统是否满足需求和验收标准 | 视频监控平台验收评审、运维管理系统验收 |

### 评审原则

- **客观量化**：所有评分基于可验证的事实和数据，不凭主观印象打分
- **维度透明**：评审维度和权重事先确定，评审过程中不随意变更
- **结论可追溯**：每个评分都有具体理由，评审结论从评分矩阵自然推导
- **适配行业**：充分考虑油气行业特殊要求（防爆、野外环境、HSE合规）

---

## 评审维度框架

### 技术方案评审维度

用于评估某一技术方案（如系统设计、架构方案）是否可行。

| 维度 | 权重 | 说明 | 评分要点 |
|------|------|------|----------|
| 技术可行性 | 25% | 方案是否可行，技术是否成熟 | 技术成熟度(TRL等级)、行业验证案例、技术团队经验 |
| 功能完整性 | 20% | 是否覆盖所有业务需求 | 需求覆盖率、功能清单完整性、边界场景覆盖 |
| 可扩展性 | 15% | 未来扩展和升级能力 | 架构灵活性、接口开放性、容量预留 |
| 安全性 | 15% | 数据安全和网络安全 | 加密机制、访问控制、等保合规、数据隔离 |
| 投资合理性 | 15% | 性价比评估 | 总拥有成本(TCO)、与投资规模匹配度、回收期 |
| 实施可行性 | 10% | 工期、团队和风险 | 工期合理性、实施团队能力、风险可控性 |

### 供应商选型维度

用于在多家候选供应商之间做对比选择。

| 维度 | 权重 | 说明 | 评分要点 |
|------|------|------|----------|
| 技术能力 | 25% | 产品功能和性能指标 | 功能覆盖度、性能参数、技术先进性、产品成熟度 |
| 行业经验 | 20% | 油气行业案例和理解度 | 中石油/中石化/中海油案例数量、行业痛点理解、方案针对性 |
| 价格 | 20% | 总拥有成本(TCO) | 采购价格、运维成本、升级费用、5年TCO |
| 服务能力 | 20% | 响应速度和保障能力 | 响应时间承诺、本地驻场能力、备件库、7×24支持 |
| 资质信誉 | 15% | 企业资质和行业口碑 | ISO认证、行业资质、成立年限、客户评价 |

### 系统验收维度

用于验证交付系统是否达到合同和技术要求。

| 维度 | 权重 | 说明 | 评分要点 |
|------|------|------|----------|
| 功能验收 | 30% | 功能是否完整实现 | 需求逐条验证、功能测试通过率、缺陷数量 |
| 性能验收 | 25% | 性能指标是否达标 | 响应时间、并发数、可用性、压力测试结果 |
| 文档验收 | 15% | 交付文档是否齐全 | 操作手册、运维手册、接口文档、培训材料 |
| 培训验收 | 15% | 培训是否到位 | 培训覆盖率、考核通过率、培训材料质量 |
| 遗留问题 | 15% | 未解决问题和整改计划 | 问题清单完整性、整改方案可行性、时间节点 |

## 评分方法

### 5分制评分标准

| 分值 | 等级 | 含义 | 判定标准 |
|------|------|------|----------|
| 5 | 优秀 | 显著超出预期 | 全面满足且有明显亮点，行业领先水平 |
| 4 | 良好 | 满足并部分超出 | 全面满足要求，部分维度表现突出 |
| 3 | 合格 | 基本满足要求 | 满足核心要求，存在少量不足但可接受 |
| 2 | 需改进 | 存在明显不足 | 核心要求部分满足，需整改后方可接受 |
| 1 | 不合格 | 严重不满足 | 核心要求未满足，存在重大缺陷 |

### 加权总分计算

```
加权总分 = Σ (维度得分 × 维度权重)

示例：某供应商得分
  技术能力: 4 × 0.25 = 1.00
  行业经验: 3 × 0.20 = 0.60
  价格:     4 × 0.20 = 0.80
  服务能力: 3 × 0.20 = 0.60
  资质信誉: 5 × 0.15 = 0.75
  ─────────────────────────
  加权总分:            3.75
```

### 通过标准

- **总分通过线**：加权总分 ≥ 3.0
- **单项底线**：任何单项维度得分不得低于 2.0
- **一票否决**：出现单项 < 2.0 的，即使总分达标也不通过

### 敏感性分析

当候选方案得分接近时（差距 < 0.3 分），需做敏感性分析：

- 调整各维度权重 ±5%，观察排名是否发生变化
- 若排名在权重微调下翻转，说明选型结论不稳定，需补充评估维度或增加评估样本
- 在报告中以表格展示不同权重方案下的排名变化

## 执行流程

### Step 1: 确认评审类型和范围

与用户确认以下信息：

- **评审类型**：技术方案评审 / 供应商选型 / 系统验收
- **评审对象**：几个候选方案/供应商，各自名称
- **评审背景**：项目名称、所属信息化领域、预算范围
- **特殊关注点**：用户是否有特别关注的维度（如"我最关心安全性"）

### Step 2: 确定评审维度和权重

- 默认使用上述标准维度和权重
- 用户可根据项目特点调整：
  - 增加/删除维度
  - 调整权重分配（所有权重之和 = 100%）
  - 修改评分标准（如将某维度的通过线提高到3.0）
- **确认动作**：向用户展示最终维度表和权重，确认后再进入评分

### Step 3: 逐项评分

对每个候选方案/供应商，按每个维度逐一评分：

```
【候选方案A：海康威视井场视频监控方案】

维度1：技术能力（权重25%）
  得分：4分（良好）
  理由：
  - 4K高清摄像头满足井场监控需求
  - 支持H.265编码，带宽占用低于竞品30%
  - 具备AI人形检测功能，可减少误报
  不足：夜间红外距离仅150m，略低于需求中的200m

维度2：行业经验（权重20%）
  得分：4分（良好）
  理由：
  - 在中石油塔里木油田有5年服务经验
  - 提供3个同类井场监控项目案例
  不足：未涉及地质录井场景的特殊需求
...
```

**评分要求**：
- 每个维度的评分必须有具体理由，不得只写"良好"或"合格"
- 涉及数据指标时标注数据来源（厂商资料/实测/公开信息）
- 明确列出每个维度的优势和不足

### Step 4: 汇总分析

将所有候选方案的评分汇总为对比矩阵：

```
┌────────────────┬────────┬────────┬────────┐
│     维度       │ 方案A  │ 方案B  │ 方案C  │
├────────────────┼────────┼────────┼────────┤
│ 技术能力(25%)  │  4.0   │  3.5   │  4.5   │
│ 行业经验(20%)  │  4.0   │  2.5   │  3.0   │
│ 价格(20%)      │  3.5   │  4.5   │  2.5   │
│ 服务能力(20%)  │  3.0   │  3.5   │  4.0   │
│ 资质信誉(15%)  │  4.5   │  3.0   │  4.0   │
├────────────────┼────────┼────────┼────────┤
│ 加权总分       │  3.78  │  3.35  │  3.55  │
│ 排名           │   1    │   3    │   2    │
└────────────────┴────────┴────────┴────────┘
```

**分析要点**：
- 排名结果及各方案优劣势总结
- 关键差异分析：哪些维度拉开了分差
- 敏感性分析（如适用）：权重变化对排名的影响

### Step 5: 评审结论

评审结论应包含以下内容：

```
一、评审结论

   推荐方案：[方案A]
   推荐理由：（2-3句话概括）

二、推荐条件
   - 例：需在合同中补充夜间红外距离≥200m的条款
   - 例：需增加井场防爆认证作为验收前置条件

三、风险提示
   - 例：该供应商在本地无备件库，紧急故障响应可能延迟
   - 例：AI功能为新增模块，稳定性需在实际使用中验证

四、下一步建议
   - 例：建议安排方案A进行现场POC测试
   - 例：建议与方案A就价格做进一步谈判

五、遗留问题清单（仅验收类）
   | 序号 | 问题描述 | 严重度 | 整改要求 | 整改期限 | 责任方 |
   |------|----------|--------|----------|----------|--------|
   | 1 | ... | 高/中/低 | ... | ... | ... |
```

## 输出格式

每次评审输出包含以下完整文件包：

### 1. 评审总览表

一张总表，所有候选方案并排对比，一目了然：

```
评审项目名称：______
评审类型：技术方案评审 / 供应商选型 / 系统验收
评审日期：______
候选方案数量：______

总览表：（各方案得分并排对比 + 排名）
```

### 2. 评分矩阵（详细版）

每个候选方案的每个维度：
- 得分
- 评分理由（3-5条具体事实）
- 优势和不足分列

### 3. 对比分析

关键差异点深度分析：
- 技术路线差异
- 价格构成差异
- 服务能力差异
- 各方案核心优势和核心短板

### 4. 评审结论

- 推荐方案及理由
- 推荐条件（前置要求）
- 风险提示
- 下一步行动建议

### 5. 遗留问题清单（仅验收类评审）

- 问题分类（功能/性能/文档/培训/其他）
- 严重度分级（高/中/低）
- 整改要求和时限
- 责任方

## 质量标准

### 评分质量要求

1. **理由具体化**：每个评分必须附带至少2条具体事实作为支撑，禁止只写"表现良好"或"基本满足"
2. **价格有据可查**：涉及价格的评分项，必须标注价格来源（厂商报价单/合同/公开价格表）
3. **技术声明可验证**：候选方案的技术能力声明应有佐证（产品手册/测试报告/第三方评测）
4. **行业案例可追溯**：行业经验评分基于可查证的案例（项目名称/时间/规模）
5. **对比口径一致**：各候选方案在同一维度下的评估内容和深度保持一致

### 油气行业特殊考量

在评审过程中需特别关注以下行业要求：

- **防爆认证**：井场设备必须具备相应防爆等级认证（Ex d/Ex i等）
- **环境适应性**：设备需适应高温、沙尘、温差大等西部油田环境
- **HSE合规**：供应商/服务商需具备HSE管理体系认证
- **数据安全**：涉及地质数据、钻井数据的系统需满足中石油数据安全管理要求
- **通信条件**：井场网络条件有限，方案需考虑低带宽、高延迟场景

## 红线规则

以下行为**严禁**：

1. **禁止编造测试结果**：不得虚构性能测试数据或POC验证结果
2. **禁止倾向性评分**：不得在没有事实支撑的情况下给某一方案异常高分或低分
3. **禁止隐瞒利益冲突**：如用户提到与某供应商存在关联关系，必须在报告中披露
4. **禁止忽略缺失信息**：当某维度的评估信息不足时，必须标注 [信息不足：xxx]，不得用猜测填补
5. **禁止跳过单项底线检查**：即使总分达标，单项 < 2.0 的必须判为不通过
6. **禁止脱离预算评估**：如用户给定预算范围，价格评分必须基于该预算范围评判合理性

以下技能可与本技能配合使用：

## 快速启动示例

### 示例1：供应商选型

用户输入：
```
3家井场视频监控方案评审：海康威视、大华、宇视，预算200万
```

输出：
1. 评审总览表 — 3家供应商5维度得分对比 + 排名
2. 评分矩阵 — 每家供应商每个维度的详细评分和理由
3. 对比分析 — 技术路线差异、价格构成差异、服务能力差异
4. 评审结论 — 推荐方案、条件、风险、下一步建议

### 示例2：技术方案评审

用户输入：
```
AI智能录井分析系统设计方案评审，天翼云方案 vs 自建GPU集群方案
```

输出：
1. 评审总览表 — 2种方案6维度对比
2. 评分矩阵 — 逐项评分及详细理由
3. 对比分析 — 云方案 vs 自建方案的核心差异（弹性/成本/数据安全/运维复杂度）
4. 评审结论 — 推荐方案及条件

### 示例3：系统验收

用户输入：
```
2024年度井场视频监控平台验收评审
```

输出：
1. 验收总览表 — 5维度验收评分
2. 详细验收记录 — 功能逐项测试结果、性能指标实测数据
3. 验收结论 — 是否通过验收、通过条件
4. 遗留问题清单 — 未解决问题、严重度、整改计划和时限
