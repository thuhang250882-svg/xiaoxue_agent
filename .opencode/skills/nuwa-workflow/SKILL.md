# 女娲：业务工作流学习

把重复且稳定的操作顺序提炼为**候选工作流**。候选在用户审核前只供预览，不自动执行、修改既有 Skill、扩大权限或向外发送文件。每个候选都应能追溯到实际任务，允许用户修改、拒绝、停用和忘记。

## 提炼流程

1. 只分析当前用户有权使用的小雪任务记录。默认记录步骤类型、文件类型、相对位置、结果和人工修正；不把报告正文、个人信息、密钥或原始附件复制进候选。
2. 比较同类任务中重复出现的触发条件、输入、操作顺序、校验点和交付方式。一次性请求、失败重试、偶然点击与未经确认的推断不算稳定习惯。
3. 写出候选：名称、适用范围、触发词、所需输入、按顺序执行的步骤、调用的 Skill/工具、每步权限、人工审批点、验收检查、输出文件及定位方式、异常退出条件、证据任务和版本。
4. 和现有 Skill 核对。优先复用专业 Skill，不复制其领域规则。遇到互相矛盾的步骤或材料不足，列出差异并请用户裁定，不自动合并。
5. 在一个历史任务上模拟回放，核对预期输入、审批点和产物是否完整。展示候选及与原做法的差异，用户批准后才启用；后续纠正应生成新版本并保留旧版本可回退。

用户要求“按上次流程做”时，先用 `workflow_learning` 列出当前工作区的已批准候选。确认候选的业务 Skill 与本次输入相符，再按步骤调用现有工具；遇到缺文件、步骤过时或审批条件变化时暂停该流程并说明原因。工作流卡片仅记录工具顺序，不能替代专业 Skill 中的详细核验要求。

## 小雪业务模式

- **录井资料审核**：分别检查报告质量和数据质量。专业结论使用 `geolog-logging-review`；缺少 MDB 或原始数据时，把数据核验标为未完成，不推断通过。交付带 Word 原生批注的副本、问题清单与可编辑的修订稿时，沿用对应文档技能。
- **周报、日报和院级汇总**：先区分正式单位材料与信息化项目七板块周报，再分别使用 `weekly-report`、`daily-report` 或 `oilfield-it-project-management`。保留来源、统计口径、字段顺序和待确认项。
- **文档交付**：记录原文件、副本、预览与最终文件的关系；校验 Word、Excel、PPT、PDF 等产物确实存在且可打开。把全部产物列在任务回复末尾，并提供预览及文件位置。无法编辑的格式不得标成可编辑。

## 权限与运行边界

- 文件读取、写入、覆盖、批量处理和外部发送分别遵守当前会话权限；工作流不能继承一次性批准，也不能替用户审批。
- 自动学习只能生成候选；批准后的每次运行仍需遵守当次权限和专业技能的校验要求。
- 记录用户的停用、纠正和删除决定；候选引用的证据被删除后，应提示重新验证。
