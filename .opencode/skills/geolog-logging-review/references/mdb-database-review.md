# MDB 原始数据与双岗位审核规则

## 适用依据

- 报告质量审核继续以 `Q/SY 01128-2020` 附录 D 和本技能专业主规则为主。
- MDB 结构与字段含义依据用户提供的 `Q/SY XJ 0222-2009《录井数据库逻辑结构》`；该 PDF 正文标注“2014年11月确认”。文件名中的年份不能替代正文版本信息。
- 标准使用 `AJLJ` 表名前缀，现场 Access 数据库可能使用 `ADLJ`。解析器可把两者作为已知别名，但输出必须保留实际表名。
- `JB` 等实库扩展字段不属于标准表 1 时，必须标记为扩展字段，不能伪称标准字段。

## 两个审核岗位

### 报告质量审核岗

检查报告结构、文字、图表、专业逻辑和多资料一致性。有 MDB 时，把报告中明确定位的井号、井深、补心高、日期、层位和完井方式等字段与原始数据库交叉核对。

MDB 与报告不一致时输出“差异待复核”，同时给出两侧原值、位置、数据库哈希和标准依据。数据库不是天然正确答案，不自动覆盖报告。

### 数据质量审核岗

检查 MDB 本身，不把结果混入报告质量问题数。当前自动检查：

- 39 张标准录井表的结构覆盖，以及标准目录外扩展表清单；
- 完井基础表 `AJLJ01`，兼容实库别名 `ADLJ01`；
- 标准关键字段及非空覆盖，当前包括 `JH`、`JHDM`、`SGDW`、`SGDH`、`LJDW`、`KZRQ`、`WZRQ`、`BXG`、`WZJS`；
- 同一数据库中标准表记录的井号归属，禁止静默混入邻井；
- `KZRQ ≤ WZRQ ≤ WJRQ`；
- `BXG` 在 `[0,20] m`，`WZJS` 在 `[50,10000] m`，`WZCS ≤ WZJS`；
- 含 `DJSD1`、`DJSD2` 的标准表满足顶界深度不大于底界深度；
- 读取记录数必须等于表行数，截断或超限时停止给出完整数据质量结论。

缺表不能直接判错。若该井没有相应业务，例如未取心、未发生井涌或未开展某项分析，应由数据质量审核岗确认“不适用”；否则按数据缺失整改。

规范值代码、全部字段类型/宽度/小数位、主外键、所有非空约束和跨表专业语义尚未全部自动化时，必须写入覆盖范围，不能声称整库审核完成。

## 工具调用与文件选择

使用 `geology_report_review`，典型参数：

```json
{
  "directory": "用户明确提供的录井目录绝对路径",
  "primaryReport": "主报告文件名.docx",
  "mdbFile": "地质录井.mdb"
}
```

- 目录只有一个明确主报告和一个 MDB 时可以自动选择；存在多个候选时必须明确文件名。
- 用户已上传报告附件时，附件作为报告来源，目录可只提供 MDB；无上传附件时从授权目录读取报告。
- 只读取目录第一层，不递归吸收邻井目录或名称相似资料。
- 使用临时副本和本机 32 位 Jet 驱动只读查询；原文件读取前后校验大小、修改时间和 SHA-256，不修改 MDB。
- MDB 不可读、加密、驱动缺失或超过安全限制时，数据质量轨道为“未完成/无法验证”，报告质量轨道仍可继续。

## 无 MDB 时的结论

必须保留两个岗位的独立状态：

| 岗位 | 状态 | 结论边界 |
| --- | --- | --- |
| 报告质量审核岗 | 已完成或按实际证据判定 | 可输出报告问题、批注和整改意见 |
| 数据质量审核岗 | 未执行 | 明确“未提供 MDB，原始数据未核验”，不得推断合格或不合格 |

最终总体结论若依赖关键原始数据，而 MDB 未提供，应把该部分列为人工复核或验收前置条件。
