## 三、必须知道的三个坑

### 坑 1：所有单元格都是文本，不是数值

`xlrd` 读出的 `cell_type` 全部为 `XL_CELL_TEXT`（返回值 1），包括 `5600.0000`、`1726.0900` 这类明显数值的字段。

**后果**：不能直接对单元格做算术，必须先 `float()` 转换；也不能假设"空单元格"是 `None`，它是空字符串 `""`。

**好处**：导出件保证字面值（含尾随 0 的小数位数）不会被改写，成品照抄即是"保持原格式"。

### 坑 2：样式高度统一，只有约 5 种 XF

源文件 152 行数据只用了极少的样式索引：

| 位置 | XF | 字体 | 字号 |
|---|---|---|---|
| 第1行 标题 | 26 | 宋体 | 30pt（height=600），加粗 |
| 第2行 日期 | 27 | Arial | 10pt |
| 第3行 表头 | 21 | 宋体 | 11pt |
| 第4行起 数据 | 24 | 宋体 | 9pt |

因此成品完全可以据此忠实还原版式，不需要 xlutils 复制整个工作簿。

### 坑 3：`施工状态` 无法用于判定存续状态

该字段是自由文本，152 行出现约 100 种取值（大量组合如 `下技套 洗井 固井 候凝`），且存在异体字 `侯凝`/`候凝` 混用。

**不要**靠它做"未录井/已完井"判定——已穷举验证，任何基于该字段的规则都无法复现历史口径。判据见 `xls-outputs.md` 第三节。

## 四、`录井系列` 是复合字段

同一口井可同时计入多个系列，源值形如：

```
综合                     91 行
一般                     23 行
气测+常规                 11 行
综合录井                   9 行     ← 与「综合」实为同一类
常规                      6 行
综合+地质导向+液面监测         2 行
综合、地化                  2 行
综合+地化                  2 行
综合、地质导向、液面监测        1 行
气测+常规、池体积检测          1 行
气测+常规+池体积监测          1 行
地质导向                   1 行
元素录井                   1 行
EISC                     1 行
```

分隔符混用：`、` `+` `，` `,` `/`。按分隔符拆分后归一化，得到：

| 系列 | 计数 | | 系列 | 计数 |
|---|---|---|---|---|
| 综合 | 98（含「综合录井」9） | | 地质导向 | 4 |
| 一般 | 23 | | 地化 | 4 |
| 常规 | 19 | | 液面监测 | 3 |
| 气测 | 13 | | 池体积监测 | 2（含「池体积检测」1） |
| 综合录井 | 9 | | 元素录井 | 1 |
| | | | EISC | 1 |

**后果**：各系列之和必定大于井数。这是字段本身的性质，不是 bug。横向合计若干系列时要注意重复计数。

## 五、源表不提供的字段

源文件**没有**以下字段，任何声称能算出它们的实现都是在编造：

- 进度/日进尺增量（无昨日井深，无法算差值）
- 队伍总数、未动用数（只有当日有井的队伍）
- 年累完成天数、月累/年累完成口数（无历史台账）
- 工作人员数、设备台数明细

需要这些时必须另行提供花名册/台账，并通过 `--roster` 之类的开关接入，禁止用比例推算。
