# 日报汇总口径与校核规则

## 一、汇总的两种基本动作

**横向拼接**（用于正文）：把各单位同名板块的句子并列排放。典型如"2.实验检测"，各单位自报原句各占一段，句首写明单位，不加总、不改写。

**纵向堆叠**（用于表格）：各单位同名表格的行依次排列，末行加合计。

只有"地质导向"一个板块需要把多家数量**相加**成一句总述。

## 二、缺报处理原则（用户已确认）

**有啥算啥，绝不推算补齐。**

- 某单位未报送，其行从相关表格中直接剔除，不由历史数据补。
- 合计数按实际到报单位重算，不沿用历史合计数。
- 成稿末尾固定一节"本日数据报送情况"，列明：到报单位清单、未报到单位清单。
- 由大单位代报的（如海外项目部由克拉玛依项目部代报）要在到报清单里括注说明。

## 三、常见缺报单位

日常编制务必核对这几家常单独报送的单位是否有件：装备研发中心、监督中心、生产保障中心、市场与生产协调科、地质研究中心（增产总承包专项日报）、海外项目部。

## 四、合计行的计算口径

合计行一律用 `%SUM` 指令由生成器自动累加，**不许手算**。

| 场景 | 指令 |
|---|---|
| 纯数值列求和 | `SUM` |
| 比率列（如动用率） | `RATE:分子列/分母列`，分子分母都取各行求和后再相除 |
| 两列之和 | `ADD:a,b`，支持多列 `ADD:a,b,c` |
| 不适用（保持占位） | `--` |

`RATE` 与 `ADD` 可引用**同一合计行左侧已算出的列**，因此可以写出"动用设备总数 = 动用数 + 合作设备动用"再算"自主施工占比 = 动用数 / 动用设备总数"这种链式依赖。

### 三条硬约束

1. **列数必须对齐**。`%SUM` 给出的指令个数与该表列数不符时，生成器直接抛错中断，不许静默补 `--`。
2. **不许前向引用**。引用列必须在同一合计行**左侧已算出**，引用右侧未算列一律抛错，不许按 0 处理。
3. **四舍五入走 `Decimal` + `ROUND_HALF_UP`**，禁用 Python 内置 `round`。内置 `round` 是银行家舍入，`round(2.5)` = 2、`round(0.5)` = 0，会与人工手算差 1，进尺这类整数列尤其容易翻车。

### `%CK`：列间平衡校验

除合计行的纵向累加外，表内还存在**横向恒等**（如"动用数 + 合作数 = 在用的设备总数"）。这类关系用 `%CK` 显式声明，写在 `%SUM` 之后、数据行之前：

```
%CK 7+9=10
%CK 8+9+10=7
```

含义是"左侧列之和 = 右侧列之和"。生成时逐数据行验算，不平的逐条列出**行名、两侧算式与差值**，默认中断生成；确认属报送单位自报矛盾时加 `--allow-unbalanced` 降级为告警并照录原值。

**`%CK` 报出的不平一律不改数**，只进校核清单交报送单位确认。判据见第六节——没有交叉验证的不平，照录原值。

## 五、八条必须跑的校验

生成成稿前逐条检查，结果进校核清单：

1. **行内恒等**：每张表按 `structure.md` 第三节列出的恒等关系验算（总数 = 分项之和）。不平的行逐行列出。
2. **合计还原**：合计行的每一列，是否等于该列各行之和。不平则说明合计是倒算或抄旧的。
3. **文表一致**：正文里的合计数必须与同名表格的合计数相等。不一致时以表格为准修正正文，并记入清单。
4. **板块间交叉**：如"液面监测"在表 6 的在用合计，必须等于正文"液面监测：动用 N 套"的 N。
5. **日期一致性**：检查各单位源件标题下的日期是否与汇总日一致。不一致的（常见跨两天的旧件）明确指出。
6. **缺报比对**：本次到报清单与上一版到报清单比对，说明新增/减少的单位。
7. **量纲一致性**：涉及"设备台数"与"井口数"的地方分别核看，不得把两者混加。
8. **列间平衡**：每张表声明的 `%CK` 全部跑一遍，不平项逐条列出（行名 + 算式 + 差值），交报送单位确认，不得自行改数。
9. **比例与源件回验**：每张含"率"列的表声明 `%CKR`（抓率×总数≠量）；关键行钉进 `--verify` 回验清单（抓抄得自洽的提取错误）。两者报出的问题同样只进清单不改数。

## 六、判定"单位自报笔误"的四条判据

只有同时满足下列判据，才可以在成稿中修正一个单位自报的数值（且必须记入校核清单）：

1. 该单位自报的**同一行内**存在另一个字段与该值直接矛盾；
2. 矛盾字段本身能与第三个字段相互验证；
3. 修正后该行全部恒等关系成立；
4. 修正值与历史汇总件一致，或至少不冲突。

实例：西南分院录井仪表自报"总数 18 / 正录 4 / 待录 0 / 待搬 4 / 等停 8 / 动用数 10 / 动用率 44%"。其中 18 × 44% = 8，且自报的"动用设备总数 8"也指向 8，而 4 + 0 + 4 = 8 ≠ 10。四条判据齐备，判定"动用数 10"为笔误、应为 8；同时总数 18 − 8 = 10，说明"等停 8"应为 10。修正后全部恒等成立，且与历史件一致。

仅有"某两处数字对不上"而缺乏交叉验证时（如玛湖数字化坐岗仪 22 总数 vs 21 在用 + 0 等停 + 0 维修，缺 1 台），**照录原值**，只在清单里提示，不得自行指定改动哪一格。

## 七、已知坑（Gotchas）

1. **`.doc` 源文件必须先转 `.docx`** 才能用 python-docx 读全文。转换走本地编辑器 SDK 的 `open_file` + `save_file`；`open_file` 返回的 `file_id` 是源文件**完整绝对路径**，regex 取 ID 时不能按 UUID 格式匹配，否则只会截到盘符 `C`。
2. **目标文件常被占用**：只要之前在本地编辑器里打开过，实例池会锁住它，`os.replace` 会被拒。覆盖前先查实例池并释放。
3. **docx 不能靠整体字节比对**：python-docx 每次写入都刷新 `docProps/core.xml` 时间戳，会出现"同尺寸不同哈希"。要证明内容零变化必须解压后**逐部件比对**，并确认唯一差异是时间戳。
4. **页边距不能从素材反演**：单位件和汇总件用的都是 Word 默认边距（2.54 / 3.17 cm），照抄等于把坏版式固化。
5. **字体要落到 eastAsia**：只设 `run.font.name` 不够，必须同时写 `w:rFonts` 的 `ascii / hAnsi / eastAsia / cs` 四个属性，中文才会生效。
6. **表格列宽合计要等于版心**（15.60 cm）。生成器的做法是最后 1 列用"版心 − 前 n−1 列"补齐，避免累计误差超框。
7. **同一文件的多处修改不能并行**：基于同一快照并发编辑，后一次会把前一次静默回滚，且工具照样报成功。同一文件的多处修改必须**串行**执行，改完回读确认。
8. **数据中心报的信息化套数是跨区域合计数**：数据中心自报"累计使用 191 套（北疆 124 + 吐哈 31 + 青海 36）"，这个 191 不能直接填进表 5 的"数据中心"行，必须按区域拆成三行分别入表，否则会与吐哈区域、青海区域重复计数。表 5 里"数据中心"这一行实际只填北疆的数字。
9. **`增产总承包业务日报` 是独立文件名**，不带"生产运行汇报"字样，容易被漏掉。汇总前务必单独找一遍。
10. **地质导向是全院唯一的"多家相加"板块**，别以为一体化中心报的数就是全院数；吐哈、西南、长庆还会各报几口。
11. **本地通道转不出真正的 `.doc`**：`save_file` 的目标路径即使写成 `.doc`，产出的仍是 docx（文件头 `504b0304`），不是 OLE 复合文档（`d0cf11e0`）。目标件保留 `.doc` 名时，必须**同时生成一份 `.docx` 副本**，否则用 Word 打开会提示"文件格式与扩展名不匹配"。
12. **调 SDK 的 arguments 一律用 `json.dumps` 生成**：路径里含反斜杠，手写 JSON 字符串时 `\U` 会被当成转义符，导致 `file_id` 变成非法值、`close_file` 报 `no editor open`。同理，从 `get_pool_status` 回包里取 `file_id` 也要走 JSON 解析，别用正则去猜。
13. **`get_pool_status` 里 `file_id` 与 `file_path` 常常不是同一个**：转档场景下 `file_id` 是源 `.doc` 路径、`file_path` 是转出的 `.docx` 路径。释放实例要用 `file_id`。
