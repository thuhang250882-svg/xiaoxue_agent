# 地质交底与录井策划核查

## 目标

对地质交底、录井策划等格式化文档做两类工作：一是「核查」——结合单井地质设计逐项排查基础数据的准确性与格式规范性；二是「生成」——按模板和地质设计数据起草文档初稿。不代替专业地质判断。

## 核查流程

1. **收集文档**：取得被核查文档（地质交底/录井策划）和对照依据（单井地质设计，必要时邻井资料、区块资料）。文档为 docx/pdf/xls 时先完整提取正文与表格内容。
2. **基础数据比对**：建立"字段—交底值—地质设计值—是否一致"对照表，至少核对：
   - 井号、井型（直井/定向/水平）、井别；
   - 设计井深、完钻井深、目的层；
   - 地理位置、构造位置、坐标；
   - 开钻日期、设计周期等时间数据；
   - 引用的区域资料、邻井资料名称与版本。
   数值类字段逐一复算或逐项比对，不一致处给出两侧原值与所在位置（章节/表名）。
3. **格式规范检查**：对照 `knowledge/templates/` 中相应模板检查章节结构、必备要素（编制/审核签字栏、日期、单位）、术语规范；标注缺项、模板残留、占位符未替换。
4. **输出差异清单**：分「数据不一致」「格式缺项」「需人工确认」三类输出；每条注明文档位置。数据不一致项按影响排序（井号/井深/坐标类为基础错误，置顶）。
5. **人工确认边界**：地质结论、分层方案、录井项目取舍属于专业判断，只提示疑问不擅自改判。

## 生成流程

1. 确认文档类型与模板（`knowledge/templates/`），无模板时向用户要格式要求。
2. 从单井地质设计提取基础数据，按模板结构填充起草；模板占位符全部替换，不得残留"XX"等待补字样。
3. 无法从依据文档确定的字段，集中列在文末"待确认清单"，由用户补充，不得编造数据。
4. 输出 docx 初稿供专业人员进行专业内容审改。

## 工作纪律

- 所有比对结论必须给出双侧出处（章节/表名/字段），不凭印象判断对错。
- 被核查文档与地质设计本身可能有误：两侧矛盾时如实列出，提示以最新有效版本为准，由地质专业人员裁定。
- 起草的文档初稿标注"初稿，待审"；涉及井控、安全的要求须人工复核后方可下发。
