# 办公文档修改交付

## 交付契约

- 保留原文件，不得覆盖。
- 审核或修改任务默认交付两份同类型文件：`标注版`保留问题说明，`最终修改版`应用已经确定的修改。
- 每条修改必须包含可定位的最小原文、替换文本和简明说明。定位失败的修改进入未匹配清单，不得声称已经写入。
- Word 使用原文批注，Excel 和 PowerPoint 使用可见的 AI 审核标记，PDF 使用高亮和批注；批注作者统一为“AI审核”。
- 修改版只应用明确的替换，不把风险说明、泛化建议或未确认结论直接写进正文。
- 生成后重新读取两份文件，核对格式、修改数和未匹配项。两份文件都要提供绝对路径并登记右侧预览。

## 执行方式

先由领域技能或模型形成结构化修改决定，再调用 `office_document_revise`：

```json
{
  "edits": [
    {
      "id": "REVIEW-001",
      "matchText": "需修改的最小原文",
      "replacement": "最终采用的文字",
      "comment": "问题及修改依据",
      "occurrence": 1
    }
  ]
}
```

合同审核先调用 `contract_review`，标书审核先调用 `tender_review`，地质录井报告先调用 `geology_report_review`。这些工具提供专业问题与证据；本技能负责把已确认的修改写回原文件副本。

## 格式边界

- 支持 `.docx`、`.xlsx`、`.pptx`、`.pdf`。
- 旧版 `.doc`、`.xls`、`.ppt` 必须先转换成 OOXML 格式，不能伪装成已完成修改。
- PDF 最终版通过定位原文后覆盖替换，复杂排版、扫描页、签章或不可提取文字必须标记人工复核。
- PowerPoint 标注版可能增加可见审核文字；最终版只保留替换后的演示内容。
