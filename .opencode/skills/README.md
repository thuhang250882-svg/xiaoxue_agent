# 监督技能编写指南：技能如何配合知识库

本目录下的监督类技能（supervision-*）与 `knowledge/` 知识库配合工作。新增或修改技能时遵循以下约定。

## 一、技能与知识库的分工

- **知识放 knowledge/，流程放技能**。SKILL.md 里不写标准条款、不写案例内容，只写"查什么、怎么查、输出什么格式、什么不能做"。
- 知识库更新（标准换版、案例新增）时技能不用改；技能优化输出格式时知识库不用动。

## 二、SKILL.md 结构（照抄现有 supervision-* 技能）

```markdown
---
name: 英文短横线名
description: 一句话功能 + 触发场景。把同事实际会说的话写进触发词，如"这个问题违反哪条标准""帮我找标准依据"。
---

# 标题

## 目标        （一段话，说明解决什么、不解决什么）
## 工作流程     （编号步骤，每步写明读哪个知识库文件）
## 输出格式     （固定模板，保证交付物稳定）
## 工作纪律     （边界：不编造、查不到说待核实、人工确认）
```

## 三、检索知识库的固定套路：索引优先

1. 先读索引表定位：`knowledge/standards/INDEX.md` 或 `knowledge/inspection_cases/INDEX.md`；
2. 再按索引给出的路径读具体文件（条款卡 clauses.md、案例卡）取原文；
3. 引用必须带出处（标准号+条款号+页码，或案例编号）。

不要跳过索引直接全文乱搜；索引是版本受控的入口，也是省 token 的关键。

## 四、引用与辅助脚本

- 技能间互相引用写技能名即可，如"违反条款须经 supervision-standard-lookup 查证"。
- 需要确定性计算/检查时，在技能目录下放 `scripts/` 脚本（参考 geolog-logging-review 的 audit_extracted_text.py），技能里写明调用命令；脚本只发现候选异常，结论仍回原文复核。
- 大段参考资料放技能目录下 `references/`（检查清单、常见问题分级等），与知识库的"权威原文"区分开。

## 五、新增一个监督技能的检查单

1. frontmatter 的 description 含同事口语触发词；
2. 工作流程每一步的知识库路径真实存在（knowledge/ 下先建好目录和索引）；
3. 输出格式模板字段与案例卡/索引表字段对齐；
4. 纪律段包含：条款只引已登记现行标准、照片不推测、查无依据标"待核实"、输出为初稿须人工确认；
5. 在小雪里实际问一句触发词试跑，确认技能被选中且路径读得到。
