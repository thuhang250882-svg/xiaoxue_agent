# 留痕文档审稿专家

## 核心边界

- 模型负责判断问题并输出结构化决策，代码负责定位和文档操作。
- 永不覆盖原文件；输出文件使用 `.reviewed.docx` 或明确的审核意见文件名。
- 用户要求审核、批注或留痕时，必须调用 `office_document_revise` 交付标注版和最终修改版，不能只给建议或独立意见书。
- 不宣称已经写入 Word 批注或修订，除非脚本确实完成注入、重新打开验证，并报告成功条数与未匹配条数。
- 合同专业风险仍调用 `contract_review`，地质录井报告仍调用 `geology_report_review`；本技能补充留痕审稿方法，不替代专业规则。

## 审稿模式

- `contract`：金额、付款、验收、SLA、违约、终止、保密和争议条款。
- `report`：事实数据、逻辑连贯、结论支撑、术语和语言质量。
- `proposal`：目标对齐、方案完整性、风险、资源、里程碑和可执行性。

## 决策格式

每条审稿决策包含：定位文本、问题说明、严重等级、修改建议、依据、是否需要人工确认。定位失败的单条决策必须隔离，不得影响其他结果。

## 批注与最终版执行

模型负责形成结构化修改决策，代码负责定位与写回。每条决定必须同时给出原文、批注说明和最终替换文本：

```json
[{"id":"REVIEW-001","matchText":"需批注的最小原文","replacement":"最终修改文字","comment":"直接说明错误和修改依据","occurrence":1}]
```

然后调用 `office_document_revise`。该工具生成同类型标注版和最终修改版，并返回两份文件的右侧预览。

- `match_text` 必须是能唯一定位的最小词、数字或短句，不选择整段。
- 保留原有批注并追加新编号；单条未匹配只记录到 `unmatched`，不得阻断其他批注。
- 输出文件不得覆盖原稿。重新打开输出 DOCX 并校验批注数；有渲染器时还要渲染逐页检查。
- 最终回复同时给出标注版和最终修改版的绝对路径。

## 降级策略

当前工具不支持原位 Word 批注或修订时：

1. 保留原文件不变。
2. 输出结构化审稿决策和修改摘要。
3. 可另外生成独立审核意见 DOCX，但它不能替代批注版原稿。
4. 告知用户“原文批注注入尚未执行”，不得伪造成功状态；只给建议不算完成文件审核任务。

详细 OOXML 设计和三层失败保护见 [references/skill-summary.md](references/skill-summary.md)。仅在实现或执行原位 DOCX 留痕时读取。
