# /项目周报 -- 从进展要点生成信息化项目周报

**适用场景**：西部钻探地质研究院巴州分公司数据中心，负责钻试修井场信息化服务、设备运维、系统研发及甲方委托项目的进度汇报。

**独立能力（无需连接器）**

- 周报标准七板块结构（完成/进行中/延期/风险/下周/决策/设备资源）
- 红黄绿灯状态判定标准（适配信息化项目量化阈值）
- 双口径输出：内部版（数据中心/分公司）与甲方版（塔里木油田/上级单位）
- 设备动态追踪（安装/维修/拆除）与人员动态管理（驻井/排班）
- 风险分级矩阵 + 常见延期原因预防清单（适配油田信息化场景）
- 需决策事项选项化（给选项不给开放题）

## 调用方式

```
/项目周报 <本周进展要点>
```

## 输入要求

用户需提供以下信息（可分批补充）：

1. **项目名称/类型**：当前项目名称或工作流类型
   - 信息化服务（钻试修井场信息化运维）
   - 设备运维（井场设备安装/维修/拆除）
   - 研发项目（A12系统、智能雪狼系统等）
   - 甲方项目（塔里木油田委托的专项任务）
2. **本周进展**：完成了什么、正在做什么、遇到什么问题
3. **版本**：内部版 / 甲方版（决定内容口径和详略）
4. **设备动态**（如适用）：本周安装/维修/拆除的设备清单及状态
5. **人员动态**（如适用）：驻井人员变化、排班调整、新增/撤减人员
6. **工作计划基准**（如有）：原计划本周应完成什么（对比实际进展）
7. **上周遗留**（可选）：上周未完成事项的跟进情况

> **分支判断——项目状态决定周报侧重**：
> - **项目按计划进行**（绿灯）-> 简报模式，聚焦下周计划和预防性风险提示
> - **轻微延迟（3-7天）**（黄灯）-> 详细说明延迟原因+追赶计划，证明"可控"
> - **重大延迟（>7天）或方向性问题**（红灯）-> 危机模式，必须提出"范围/时间/资源 三选二"的决策请求

> **分支判断——周报版本决定内容口径**：
> - **内部版**（给数据中心团队/分公司管理层）-> 含内部资源消耗、成本信息、团队问题、内部风险、人员排班详情
> - **甲方版**（给塔里木油田项目负责人/上级单位）-> 侧重进展、交付物、需甲方配合事项，措辞更正式；隐去内部资源和成本细节，不暴露内部人员问题

## 执行流程

### 步骤一：信息解析与分类

- 将用户输入拆解为：已完成 / 进行中 / 延期 / 风险
- 识别隐含的决策需求和资源缺口
- 对模糊描述追问确认（标注[待确认]）
- 特别关注：设备状态变化、井场覆盖范围变动、甲方临时需求

> 注意：用户经常低报风险和高报进度。如用户说"基本完成"应追问具体完成百分比；如说"有点延迟"应追问延迟几天及影响范围；如说"设备已到位"应追问是否完成安装调试。

### 步骤二：状态灯判定

**红黄绿灯判定标准**（适配信息化项目）：

| 状态 | 判定标准 | 管理含义 | 后续行动 |
|------|---------|---------|---------|
| **绿灯** | 按计划推进，无重大问题；进度偏差<3天；设备运行正常率>98% | 项目可控，无需干预 | 常规周报即可 |
| **黄灯** | 进度偏差3-7天；或有中等风险（如设备到货延迟、甲方需求变更、网络不稳定影响数据传输） | 需关注，可能需要调整 | 说明追赶计划，标注需关注事项 |
| **红灯** | 进度偏差>7天；或有重大风险（如设备故障影响生产、甲方投诉、安全事故、关键系统宕机超4小时） | 需立即决策和干预 | 必须提出决策请求，给出选项 |

### 步骤三：周报结构生成（七大板块）

按以下七大板块组织内容：

**1. 本周完成事项**（按优先级列出已交付成果）
- 每条须有可验证的交付成果
  - 好的写法："完成克深XX井、哈得XX井共3口井的视频监控设备安装调试，已接入A12平台"
  - 不好的写法："完成了设备安装"（不够具体）
  - 好的写法："A12系统运维本周处理工单12个，关闭率100%，平均响应时间2.3小时"
  - 不好的写法："处理了一些运维工单"

**2. 进行中事项**（标注进度百分比与预计完成时间）

| 事项 | 进度 | 责任人 | 预计完成 | 是否在计划内 |
|------|------|--------|---------|------------|
| XX井场网络部署 | 70% | 张三 | 11月15日 | 是 |
| 智能雪狼V2.0测试 | 45% | 李四 | 12月1日 | 延迟3天 |

**3. 延期事项**（说明延期原因与补救计划）

**常见信息化项目延期原因及预防清单**：

| 延期来源 | 常见原因 | 预防措施 |
|---------|---------|---------|
| **甲方侧** | 井场施工进度滞后，不具备安装条件 | 提前与钻井队沟通确认井场就绪状态 |
| **甲方侧** | 需求变更/新增（如追加监控点位） | 变更管理流程+影响评估+书面确认 |
| **甲方侧** | 审批流程长（如入井许可证、网络接入审批） | 提前提交申请材料+跟踪审批进度 |
| **供应链** | 设备到货延迟（防爆设备采购周期长） | 关键设备提前备货+建立安全库存 |
| **供应链** | 设备型号不匹配需退换 | 采购前与甲方确认技术规格+到货验收 |
| **团队侧** | 驻井人员调配冲突（多井场同时施工） | 提前排班+建立应急人员储备池 |
| **团队侧** | 技术方案调整（现场条件与预期不符） | 前期踏勘+技术交底+预留调整时间 |
| **外部** | 极端天气影响井场作业 | 关注天气预报+制定恶劣天气应急预案 |
| **外部** | 网络运营商线路故障 | 双链路备份+4G应急通道 |

**4. 风险与问题**

**风险分级标准**：

| 级别 | 影响x概率 | 说明 | 处理方式 |
|------|---------|------|---------|
| **高风险** | 影响大 + 概率高 | 可能导致系统停机影响生产、甲方通报批评、安全事故 | 需立即决策，本期周报必须升级 |
| **中风险** | 影响中 或 概率中 | 可能影响部分井场服务或项目节点 | 需持续关注，制定预案 |
| **低风险** | 影响小 + 概率低 | 影响有限，可控 | 纳入监控清单，无需专项行动 |

**5. 下周计划**（明确责任人与交付日期）

**6. 需决策/协调事项**——这是周报最核心的板块
- 每个决策事项须包含：**背景**（为什么需要决策）-> **选项**（给2-3个选项，含利弊分析）-> **建议**（推荐哪个选项及理由）
- **不给开放题**：不写"下周方向请领导指示"，而写"下周建议聚焦方案A（原因XX），或可选择方案B（利弊XX），建议选A"
- 常见需决策事项：设备采购审批、人员调配请求、甲方协调需求、技术方案选型

**7. 设备/资源动态**
- **设备状态汇总**：安装/维修/拆除/报废数量及明细
- **设备运行指标**：在线率、故障率、平均修复时间
- **人员动态**：驻井人数、排班变化、人员增减
- **资源消耗**：备品备件库存、车辆使用情况

### 步骤四：关键指标提炼

- 提取本周关键里程碑达成情况
- 计算项目整体进度
- 标注红黄绿灯状态

**关键指标追踪表**：

| 指标 | 计划值 | 实际值 | 偏差 | 状态 |
|------|-------|-------|------|------|
| 项目整体进度 | XX% | XX% | +/-XX% | G/Y/R |
| 井场覆盖率（信息化覆盖井场数/总井场数） | XX/XX | XX/XX | - | G/Y/R |
| 设备在线率 | >98% | XX% | - | G/Y/R |
| A12工单关闭率 | >95% | XX% | - | G/Y/R |
| 运维响应时间 | <4小时 | XX小时 | - | G/Y/R |
| 关键里程碑 | 按期/延期 | - | - | G/Y/R |

### 步骤五：版本适配与输出

**内部版额外内容**（仅内部版包含）：
- 团队人力投入统计（人天/工时）
- 成本执行情况（已发生费用 vs 预算）
- 内部协调问题（跨部门/跨班组）
- 人员状态（请假、培训、考核）
- 内部改进建议

**甲方版注意事项**：
- 措辞更正式，体现专业性和服务态度
- 突出成果和交付物，弱化内部困难
- 需甲方配合的事项明确列出，附具体时间节点
- 不暴露内部成本、人员问题等敏感信息
- 文件命名格式参考："西部钻探信息化服务项目部周工作汇报含A12（M.DD-M.DD）"

**输出方式**：
- 以 Markdown 格式直接输出完整周报
- 用户可复制到 Word/WPS 进行排版后提交

## 质量标准

- **完整性**：七大板块缺一不可，无内容的板块标注"本周无"
- **可追溯**：每项完成事项对应可验证的交付成果（不接受"进行中"作为完成描述）
- **风险前置**：风险描述包含影响范围、概率和应对方案
- **决策友好**：需决策事项提供背景、选项和建议，而非仅抛问题
- **时间明确**：所有计划事项均标注截止日期和责任人
- **状态可视**：整体状态用红黄绿灯直观呈现
- **偏差量化**：延期和风险须量化（偏差几天、影响多少口井/多少个系统），不可只定性
- **双口径一致**：内部版和甲方版的核心事实一致，仅表达方式和信息深度不同

## 红线规则

1. **不隐瞒延期和风险**：周报是项目健康度的晴雨表，隐瞒延期等于放大风险。甲方迟早会知道，主动通报比被动发现更能赢得信任
2. **不虚报完成状态**：标注"完成"的事项必须有交付物证据。"设备安装完成"意味着已安装调试并接入系统，不是"设备已送到井场"
3. **需决策事项不给开放题**：不可写"请领导指示"，必须给出具体选项和推荐建议
4. **不回避甲方侧问题**：如果甲方原因导致延期，须在甲方版中以中性措辞如实反映（如"因井场施工进度调整，设备安装推迟至下周"），不能把甲方的锅背在自己身上
5. **周报按时提交**：信息化项目周报通常在每周五下午或下周一上午提交，迟交影响上级汇总
6. **不编造数据**：所有数字必须可追溯，设备在线率、工单处理数等须来自系统实际记录

## 灰色地带处理

1. **进度难以精确量化** -> 将模糊工作拆分为可量化的里程碑（如"网络部署"拆为：布线完成/设备上架/配置调试/联调通过），或用完成井场数/总井场数来衡量
2. **甲方原因导致延期但不宜直接指出** -> 用中性措辞描述，如"受井场作业条件影响"而非"甲方没把路修好"。内部版可写明具体原因
3. **团队成员表现问题** -> 周报中不点名批评，描述为"XX模块需补充完善"，人员问题通过内部管理渠道解决
4. **好消息与坏消息如何平衡** -> 原则是"先成果后风险"——先展示本周成果和进展，再提出问题和风险，最后给出解决方案
5. **多个项目同时汇报** -> 按项目分节，每个项目独立标注RAG状态，开头附项目组合总览表
6. **甲方临时加塞任务** -> 在"本周完成"或"进行中"中如实记录，同时评估对原计划的影响并在"风险"或"需决策"中提出

## 输入不足处理

- 仅提供本周进展要点时：输出基础周报框架，标注"信息有限，建议补充项目名称、设备动态、人员动态后获得更完整周报"
- 缺少关键信息时：主动向用户追问最重要的 2-3 个数据点（如项目名称、涉及井场、设备状态）
- 绝不编造数据、井号或运维指标——无法验证的信息标注[待确认]
- **快速模式**：用户提供完整进展信息 -> 直接输出结构化周报
- **引导模式**：用户仅说"帮我写周报" -> 先追问项目名称和本周进展，再结构化输出

## Agent 工具增强

- **WebSearch**：搜索油田行业动态、政策变化、极端天气预警等外部风险信号，补充风险板块
- **文件处理**：支持读取用户上传的工作计划Excel、上周周报、设备台账、A12系统导出报表等，自动对比计划vs实际
- **代码执行**：进度计算、设备在线率统计、工单处理趋势分析等使用Python确保精度
- **图像识别**：可解读用户上传的井场照片、设备截图、系统监控截图等

## 相关技能

- `/写报告`：周报积累的数据和发现是阶段性报告和年度总结的素材来源
- `/方案框架`：周报发现的进度偏差可用于调整项目实施方案
