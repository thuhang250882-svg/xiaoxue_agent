# /标杆对比 -- 技术方案与供应商对比选型

**适用场景**：石油行业信息化项目的技术方案对比、供应商选型评估、产品选型对比、行业对标分析。

**核心能力**：
- 四种对比类型自动分支（供应商选型/技术方案/产品选型/行业对标）
- 七维度加权评分矩阵（功能/技术/价格/服务/经验/扩展/信创）
- 1-5分评分标准明示，每个打分须有理由
- 敏感性分析：权重变动对排名影响测算
- 选型建议 + 风险提示 + 数据缺口透明标注

## 调用方式

```
/标杆对比 <对比对象 + 对比目的>
```

## 输入要求

1. **对比对象**：2-5个供应商/技术方案/产品（附简要描述）
2. **对比目的**：供应商入围筛选 / 最终选型决策 / 技术方案论证 / 产品采购
3. **对比类型**：供应商选型对比 / 技术方案对比 / 产品选型对比 / 行业对标（未指定时自动识别）
4. **重点维度**：全面七维扫描 / 聚焦特定维度（如重点关注价格和服务）
5. **已有数据**：报价单、技术参数表、测试报告、用户反馈等
6. **预算范围**：项目预算上限或参考区间（如已知）

> 分支判断——对比类型自动识别：
> - 输入为2-5家供应商名称 → **供应商选型对比**
> - 输入为不同技术路线（如自研vs外采） → **技术方案对比**
> - 输入为具体产品型号 → **产品选型对比**
> - 输入包含"行业最佳实践"、"标杆"等词 → **行业对标**

## 对比类型分支

### 分支A：供应商选型对比

**典型场景**：广陆 vs 晴和井场信息化设备、3家AI视频监控供应商选型、录井仪供应商入围评审

**分析重点**：
- 供应商资质与准入条件（中石油/中石化供应商目录、HSE资质）
- 功能完整性与技术参数对比
- 价格对比（设备单价、集成费、年度运维费、TCO）
- 服务能力（响应时间、驻场能力、备件库）
- 行业案例（油田部署经验、用户评价）
- 综合评分与选型建议

### 分支B：技术方案对比

**典型场景**：井场数据采集自研 vs 外采 vs 合作开发、数据中心容灾方案A vs B、录井数据上云 vs 本地部署

**分析重点**：
- 各方案技术架构与核心差异
- 技术成熟度与风险等级
- 实施周期与资源需求
- 全生命周期成本（建设+运维+升级）
- 可扩展性与未来演进空间
- 综合推荐与实施路径建议

### 分支C：产品选型对比

**典型场景**：GPU服务器选型（浪潮vs华为vs曙光）、井场边缘计算网关对比、工业级交换机选型

**分析重点**：
- 核心技术参数逐项对比
- 环境适应性（防爆、温度、防尘防水）
- 兼容性与生态（与现有系统的对接）
- 价格与供货周期
- 售后政策与质保条款

### 分支D：行业对标

**典型场景**：我方数据中心建设水平与行业最佳实践对比、信息化投入占比与同行业对标

**分析重点**：
- 行业最佳实践描述与来源
- 我方现状与标杆的量化差距
- 差距根因分析（能力/资源/战略）
- 追赶路径与阶段目标

## 评价维度体系

根据对比类型选择适用的评价维度，默认全覆盖，用户可调整权重：

| 维度 | 权重建议 | 评价内容 | 评分要点 |
|------|---------|---------|---------|
| **功能完整性** | 20% | 核心功能覆盖率、差异化特性、与需求匹配度 | 功能清单逐项对比，缺失功能标注 |
| **技术先进性** | 15% | 技术架构、技术路线前瞻性、自主知识产权 | 是否采用主流/先进技术，有无技术锁定风险 |
| **价格合理性** | 20% | 设备/软件单价、集成费、运维费、TCO(3-5年) | 价格来源标注，TCO全口径计算 |
| **服务能力** | 15% | 售后响应时间、现场服务覆盖、备件供应、培训支持 | 响应SLA、驻场能力、新疆区域服务网点 |
| **行业经验** | 15% | 中石油/中石化/中海油体系部署案例、油田现场经验 | 案例数量、规模、可验证性、用户口碑 |
| **可扩展性** | 10% | 系统扩展能力、接口开放性、未来升级路径 | 是否支持横向扩展、标准接口、模块化 |
| **信创合规** | 5% | 国产化率、信创目录入选、涉密适配 | 是否在信创产品目录、国产CPU/OS适配 |

> 权重说明：以上为默认建议权重，用户可根据项目优先级调整。如价格敏感型项目可将"价格合理性"调至30%，"信创合规"调至0%。所有维度权重之和必须等于100%。

## 评分标准（1-5分制）

| 分数 | 等级 | 通用标准 |
|------|------|---------|
| **5分** | 优秀 | 完全满足或超出需求，有明显竞争优势，行业领先水平 |
| **4分** | 良好 | 满足需求，有小幅优势或亮点，高于行业平均 |
| **3分** | 合格 | 基本满足需求，无明显短板，行业平均水平 |
| **2分** | 不足 | 部分不满足需求，存在明显短板，低于行业平均 |
| **1分** | 严重不足 | 大部分不满足需求，有关键性缺陷或风险 |

**各维度评分细则示例（功能完整性）**：

| 分数 | 功能完整性标准 |
|------|-------------|
| 5分 | 100%覆盖需求功能清单，且有3项以上差异化增值功能 |
| 4分 | 95%以上覆盖需求功能清单，有1-2项增值功能 |
| 3分 | 80-95%覆盖需求功能清单，无增值功能 |
| 2分 | 60-80%覆盖需求功能清单，部分核心功能缺失 |
| 1分 | 低于60%覆盖率，多项核心功能缺失 |

> 每个维度的每个评分必须附带**评分理由**（1-2句话说明为什么给这个分数），不可只给数字不给依据。

## 执行流程

### 第一步：确认对比框架

1. 确认对比类型（供应商/技术方案/产品/行业对标）
2. 确认对比对象清单（2-5个）
3. 确认评价维度和权重（使用默认或用户自定义）
4. 确认数据来源（用户提供/公开搜索/两者结合）

### 第二步：信息搜集与整理

1. 搜集各对比对象的技术参数、价格、案例等信息
2. 按信息源可信度分级标注（Tier1-5）
3. 构建对比矩阵原始数据表
4. 标注数据缺失项[待补充]和数据年份

### 第三步：评分与对比分析

1. 按维度逐项评分（1-5分），每项附评分理由
2. 计算加权总分：总分 = 各维度得分 x 对应权重 之和
3. 进行敏感性分析：关键维度权重变动+/-5%时排名是否变化
4. 列出各选项的优劣势清单

### 第四步：输出选型建议

1. 给出推荐排名（首选/备选/不推荐）
2. 阐述推荐理由（基于评分结果的量化论证）
3. 提示首选方案的主要风险和应对措施
4. 标注数据缺口对结论可靠性的影响

## 质量标准

- **评分有据**：每个1-5分评分必须附1-2句评分理由，不可只给分数
- **价格有源**：所有价格数据须标注来源（报价单/招标价/行业参考），标注日期
- **案例可验**：引用的行业案例须可验证（项目名称、业主方、时间范围）
- **权重透明**：维度权重须明示，调整权重时须展示排名变化
- **MECE对比**：对比维度不重不漏，覆盖用户关心的核心要素
- **优劣势均衡**：每个选项既列优势也列劣势，不做片面呈现
- **建议可行动**：选型建议须具体到"选谁、什么条件下选、注意什么风险"

## 红线规则

1. **绝不编造供应商报价或技术参数**：无法获取的标注[待补充]，不可虚构
2. **绝不虚构行业案例**：不可编造不存在的部署项目或用户评价
3. **评分不可无依据偏向**：每个分数必须有客观理由，不可预设结论再凑分数
4. **不隐瞒信息不完整**：如果某些维度信息不足，须明确标注对评分可靠性的影响
5. **不做绝对性推荐**：选型建议表述为"基于当前信息的推荐"，非"必须选择"
6. **利益冲突披露**：如果信息主要来自某供应商自行提供，须标注"[信息来源：供应商X自述，建议独立验证]"

## 灰色地带处理

1. **价格信息不对称**：不同供应商报价口径不同（含税/不含税、含/不含运费安装），须统一口径后再对比，标注"[价格口径：含税含运费]"
2. **功能对比无统一标准**：不同供应商功能命名和分类不一致时，按用户需求功能清单统一映射，无法对应的功能标注"[功能对应关系待确认]"
3. **案例真实性存疑**：供应商声称的案例无法独立验证时，标注"[案例来源：供应商自述，未独立验证]"，建议用户联系案例方确认
4. **信息严重不对称**：某选项信息极度匮乏（如新进入者无公开资料），须在报告中明确说明，评分标注"[信息不足，评分仅供参考]"

## 输入不足处理

- 仅提供对比对象名称时：输出对比框架和建议的评价维度，标注"信息有限，建议补充技术参数和报价后获得完整对比"
- 缺少关键信息时：主动追问对比目的、重点维度、预算范围
- 绝不编造数据——无法获取的信息标注[待补充]
- **快速模式**：用户提供充分数据 → 直接执行完整评分矩阵
- **引导模式**：用户仅给出供应商名称 → 先输出对比框架，追问数据和重点维度
