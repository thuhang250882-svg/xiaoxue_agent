# 环节 2：格式合规审核清单

## 支持矩阵

| 格式 | 直接入库 | 处理方式 |
|------|---------|---------|
| .txt / .md / .csv | ✅ | `import` 直入 |
| .docx / .xlsx | ✅ | `import` 直入（docx 取正文，xlsx 取表格） |
| .pdf（有文字层） | ✅ | `import` 直入，自动带页码定位 |
| .pdf（纯扫描件，0 文字层） | ⚠️ 两步 | ① `pdfkit.py extract_text --input <PDF> --ocr_fallback`（内置 RapidOCR，离线）→ 全文合并存 .txt ② `import` 传 `paths=[PDF]` + `ocr_text_path=[txt]` |
| .doc / .xls（旧格式） | ⚠️ | 建议提交人转存 docx/xlsx 后入库；确需入库的按实际解析能力评估 |
| 加密 PDF | ❌ 先解密 | 引导：`pdfkit.py decrypt --input <file> --output <out> --password <密码>`，解密件入库 |
| 图片 / 音频 / 视频 | ❌ | 当前版本不支持，退回提交人 |

## 审核清单（逐项打勾）

- [ ] 文件可正常打开，非零字节
- [ ] 内容与资料名称相符（抽查首页/首表）
- [ ] 文字层检查：扫描件（0 字符）走 OCR 两步入库；乱码（CID）等同扫描件
- [ ] OCR 产物抽查：抽取 2-3 页人工比对原文，字符准确率目视 ≥95%；空白页在登记表标注页码
- [ ] 加密件已解密为明文版本
- [ ] 大文件（>50MB）入库后核对 `paragraphCount > 0`（防"入库成功但检索为空"）
- [ ] 敏感信息脱敏：身份证号、银行卡号、未公开商业数据不入库

## 常见退回原因

| 原因 | 处理 |
|------|------|
| OCR 质量差（乱码率目视 >10%） | 提高源文件扫描质量后重试，或改用文字版 |
| 内容与名称不符 | 退回提交人更正名称或更换文件 |
| 来源不明 / 涉密 | 拒收（见环节 1 红线） |

## 交付物

`格式审核结论.md`：每份资料一行（合格直入 / 已OCR入库 / 已解密入库 / 退回+原因）。
