# 监督案例入库与检索

## 目标

双向维护监督检查案例库：把新发现的问题结构化存入案例库（入库），并按需快速找出类似历史案例（检索）。案例库是检查经验沉淀的核心资产，入库质量决定后续检索价值。

## 入库流程

1. **采集信息**：从用户描述、照片识别结果（supervision-photo-check 输出）或既有问题清单中提取案例要素。缺失要素逐项向用户确认：发现日期、井号/场所、作业单位、小队、责任人、问题分类、整改要求。
2. **确定分类**：按 `inspection_cases/README.md` 的六类确定归属目录；跨类问题以直接违反条款对应的类别为准。
3. **核实条款**：违反条款必须经 supervision-standard-lookup 在已登记标准中查证；查不到依据时填"待核实"，不得凭印象写条款号。
4. **生成案例卡**：按 `inspection_cases/README.md` 的案例卡模板生成 `.md` 文件，文件名 `<日期>-<井号或单位简称>-<序号>.md`，存入对应分类目录。
5. **登记索引**：在 `inspection_cases/INDEX.md` 追加一行，编号规则：类别码-年份-流水号（EZ/SC/JY/JK/ZL/LC）。
6. **批量入库**：用户提供历史问题汇总表（Excel/表格）时，逐行转成案例卡，先生成入库清单供用户核对，确认后批量写入；同一问题涉及多个单位的分别建卡。

## 检索流程

1. 从用户提问提取检索维度：问题类型、单位、小队、井号、时间段、条款号。
2. 先查 `INDEX.md` 定位候选案例，再读取案例卡原文核对相关性。
3. 输出相似案例清单：案例编号、问题摘要、违反条款、当时整改要求、整改结果；按相似度/时间排序。
4. 检索结果为空时明确告知，并建议扩大检索维度（如放宽时间范围或换关键词）。

## 维护纪律

- 入库内容按监督中心要求脱敏后再写入；照片只存编号，不入库存图。
- 整改完成后用户告知结果时，更新对应案例卡的"整改情况"字段，不新建案例。
- 案例卡写入后必须复核：文件已存入正确分类目录、INDEX.md 已登记、编号无重复。
- 不修改他人已入库案例的问题定性；发现既往案例条款引用有误时，提示用户确认后再更正并留痕。
