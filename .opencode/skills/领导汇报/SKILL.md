# /领导汇报 -- 从汇报要点生成国企领导汇报材料

**适用场景**：西部钻探地质研究院巴州分公司数据中心，向上级领导、甲方领导、公司管理层进行工作汇报。涵盖定期汇报、专项汇报、项目检查汇报、费用申请、方案评审、年度谋划等多种场景。

**独立能力（无需连接器）**

- 多场景汇报材料生成（定期汇报/专项汇报/项目检查/费用申请/方案评审/年度谋划）
- 六大板块标准结构（定期汇报专用模板）
- Q&A问答预案生成（基于真实领导关注点预判5-10个问题）
- 国企汇报语言风格打磨（正式、数据驱动、结论先行）
- 汇报技巧提醒（实战可用的临场建议）
- 费用申请专项论证结构

## 调用方式

```
/领导汇报 <汇报要点 + 场景 + 需决策事项>
```

## 输入要求

| 必填项 | 说明 | 示例 |
|-------|------|------|
| 汇报场景 | 定期汇报/专项汇报/项目检查/方案评审/费用申请/年度谋划 | "智能雪狼系统中期检查汇报" |
| 汇报对象 | 上级领导/甲方项目负责人/公司管理层/专家组 | "塔里木油田信息化处领导" |
| 核心内容 | 工作进展、关键成果、存在问题、需支持事项 | "系统开发完成80%，需追加60万经费" |

可选补充（影响汇报策略和深度）：

| 可选项 | 影响 | 示例 |
|-------|------|------|
| 决策请求 | 需要领导拍板的具体事项 | "是否批准追加60万经费用于外场测试" |
| 汇报时长 | 影响材料详略程度 | "15分钟汇报+10分钟问答" |
| 敏感事项 | 需特别注意措辞的内容 | "设备租赁到期但甲方未续签合同" |
| 前期反馈 | 上次汇报后领导的指示 | "上次领导要求加快进度" |
| 数据支撑 | 可用的量化数据 | "准确率99.25%，已在12口井验证" |

> **分支判断——快速模式 vs 引导模式**
> - **快速模式**：用户同时提供汇报场景、核心内容、决策请求 -> 直接进入步骤一
> - **引导模式**：用户仅说"帮我准备汇报材料" -> 追问：(1) 什么场景的汇报？(2) 汇报给谁？(3) 最核心的3个要点是什么？(4) 有没有需要领导拍板的事项？(5) 有没有需要解释或防守的敏感问题？——收集完毕后进入步骤一

## 执行流程

### 步骤一：确定汇报类型与沟通策略

> **分支判断——汇报场景决定材料结构和沟通方式**

| 汇报场景 | 判断条件 | 材料形式 | 沟通方式 | 时间控制 |
|---------|---------|---------|---------|---------|
| **定期汇报**（年度/半年/季度） | 常规周期性汇报，全面展示工作成果 | 六大板块结构化报告 | 会议汇报 20-30min | 汇报15min+问答15min |
| **专项汇报** | 针对特定问题或事件的专题汇报 | 背景->现状->问题->方案->需支持事项 | 专题会 15-20min | 汇报10min+讨论10min |
| **项目检查汇报** | 科研项目/工程项目阶段性检查 | 项目概况->目标达成->技术突破->问题->计划->经费 | 检查会 20-30min | 汇报15min+问答15min |
| **费用申请/情况说明** | 申请追加经费或说明费用变动 | 背景->必要性->测算->对比->建议 | 审批会 10-15min | 汇报8min+讨论7min |
| **方案评审汇报** | 技术方案或实施方案评审 | 需求分析->方案设计->可行性->风险->实施计划 | 评审会 20-30min | 汇报15min+评审15min |
| **年度谋划会** | 下一年度工作规划汇报 | 回顾总结->形势分析->目标设定->重点任务->资源需求 | 谋划会 20-30min | 汇报15min+讨论15min |

### 步骤二：国企汇报五大原则

在生成材料前，始终贯彻以下原则：

1. **结论先行**：先说结论和建议，再展开论证。领导时间宝贵，先让他们知道你要什么、建议什么
2. **用数据说话**："准确率99.25%"比"效果显著"有说服力十倍。每个论点尽量配一个数字
3. **先肯定再解释**："您提的这个问题确实很关键..."——先认同再展开，不直接否定领导关切
4. **诚实面对问题**：主动说明问题+解决思路。领导最忌讳的是"被意外"——已知的风险叫"管控"，被领导问出来的风险叫"失职"
5. **控制篇幅**：汇报材料精炼，不堆砌信息。宁可让领导追问"还有呢"，也不要让领导觉得"说完了吗怎么还没完"

### 步骤三：生成汇报正文

根据汇报类型选择对应结构：

---

#### 类型一：定期汇报（六大板块模板）

适用于年度/半年/季度工作汇报，是最常见的汇报形式。

**一、工作概况**
- 本期工作总体情况和定位
- 用一段话概括全貌（200字以内）

**二、关键数据**

| 指标 | 本期 | 上期 | 同比 | 说明 |
|------|------|------|------|------|
| 信息化覆盖井场数 | XX | XX | +XX% | |
| A12系统可用率 | XX% | XX% | +X% | |
| 运维工单处理量 | XX个 | XX个 | +XX% | |
| 设备在线率 | XX% | XX% | - | |
| 项目验收通过率 | XX% | XX% | - | |

**三、重点进展**
- 按重要程度排列，每条含成果描述+量化数据
- 通常3-5条，不超过7条

**四、问题与风险**
- 如实列出当前面临的问题
- 每个问题附解决思路或已采取的措施
- 不回避但也不夸大

**五、下步计划**
- 按时间节点排列
- 每项计划附责任人和预期成果

**六、需要支持的事项**
- 需要上级/甲方协调或决策的具体事项
- 每项须说明背景、原因、建议方案

---

#### 类型二：专项汇报

适用于针对特定问题的专题汇报（如设备租赁危机应对、坐岗仪推广方案等）。

**结构**：背景 -> 现状分析 -> 问题/风险 -> 建议方案 -> 需支持事项

- **背景**：为什么做这个专项汇报（2-3句话）
- **现状分析**：用数据描述当前状态
- **问题/风险**：核心问题是什么，影响有多大
- **建议方案**：给出2-3个可选方案，分析利弊，明确推荐
- **需支持事项**：具体需要领导做什么

---

#### 类型三：项目检查汇报

适用于科研项目阶段性检查（如智能雪狼系统中期检查、A12系统验收等）。

**结构**：
1. **项目概况**：项目背景、目标、总体技术路线（简要）
2. **阶段目标达成**：对照任务书/合同逐项核查完成情况

| 阶段目标 | 计划指标 | 实际达成 | 完成状态 |
|---------|---------|---------|---------|
| 目标1 | XX | XX | 完成/部分完成/未完成 |

3. **关键技术突破**：本期技术亮点和创新点
4. **存在问题**：技术难点、进度偏差、资源不足等
5. **下步计划**：后续工作安排和关键节点
6. **经费执行**：预算使用情况

| 费用科目 | 预算金额 | 已执行 | 执行率 | 说明 |
|---------|---------|-------|-------|------|

---

#### 类型四：费用申请/情况说明

适用于追加经费申请、费用变动说明（这是用户非常常见的场景）。

**结构**：
1. **背景说明**：项目/任务基本情况（简要，领导已知的内容不重复）
2. **必要性论证**：为什么需要这笔费用——不花这笔钱会怎样
3. **费用测算**：详细的费用构成和测算依据

| 费用项目 | 金额（万元） | 测算依据 | 备注 |
|---------|------------|---------|------|
| 设备采购 | XX | 型号XX，单价XX，数量XX | |
| 安装施工 | XX | XX井场 x XX元/井场 | |
| 其他费用 | XX | | |
| **合计** | **XX** | | |

4. **对比分析**：投入产出分析、与同行业对比、不投入的风险
5. **结论建议**：明确申请金额和用途，给出审批建议

---

#### 类型五：方案评审汇报

适用于技术方案或实施方案的评审会议。

**结构**：需求分析 -> 方案设计 -> 可行性论证 -> 风险分析 -> 实施计划 -> 资源需求

---

#### 类型六：年度谋划会汇报

适用于下一年度工作规划的汇报。

**结构**：本年度回顾 -> 形势分析（政策/技术/业务需求变化） -> 年度目标 -> 重点任务（3-5项） -> 资源需求 -> 需支持事项

### 步骤四：Q&A问答预案（核心产出）

> **关键特征**：这是本技能最重要的附加功能。基于用户实际工作中"问答速查手册"的模式——在汇报前预判领导可能提出的问题，准备结构化的回答要点，确保临场应对从容。

在汇报正文之后，生成Q&A预案部分：

**4.1 预判问题生成规则**

根据汇报类型和场景，预判5-10个领导最可能提出的问题。问题来源分类：

| 问题类别 | 典型问题 | 出现频率 |
|---------|---------|---------|
| **进度/计划类** | "为什么延迟？""什么时候能完成？""有没有赶上来的方案？" | 高 |
| **技术方案类** | "为什么选这个方案？""有没有考虑过XX方案？""技术成熟度如何？" | 高 |
| **经费类** | "预算够不够？""投入产出比是多少？""能不能少花点？""钱花到哪了？" | 高 |
| **风险类** | "最大风险是什么？""出问题怎么办？""最坏情况是什么？" | 中 |
| **推广类** | "能不能推广到其他区块？""其他油田有没有类似做法？" | 中 |
| **对标类** | "跟行业最好水平比差多少？""塔里木其他队伍怎么做的？" | 低 |
| **人员类** | "人手够不够？""需要增加编制吗？""外包比例多少？" | 中 |
| **安全类** | "信息安全有没有保障？""数据会不会泄露？" | 中（信息化项目） |

**4.2 回答要点格式**

每个预判问题配3-5条回答要点，格式如下：

```
### Q1：[预判问题]
**回答要点**：
1. [要点1——先给结论]
2. [要点2——配数据支撑]
3. [要点3——补充说明或案例]
4. [要点4——如有]
**数据备查**：[相关数据来源或备查文档位置]
```

**4.3 万能回答模板**

对于未能预判的突发问题，提供以下万能回答框架：

- **争取时间型**："这个问题非常关键，我从两个维度回答——目前掌握的情况是[已知信息]，更精确的数据我可以在[时间]前给您一个完整的分析。"
- **承认不足型**："坦白说，这个方面我们的分析还不够深入。初步判断是[方向性结论]，我建议用[X]时间做一个专项分析后再向您汇报。"
- **转移聚焦型**："您提的这个角度很重要。从我们目前的工作来看，与此最相关的是[已有工作成果]，我展开说一下..."
- **化解质疑型**："您说得对，这确实是我们需要正视的问题。我们已经意识到并采取了三项措施：[措施1/2/3]。"

**4.4 Q&A预案质量控制**

- 回答要点必须配数据，不接受"效果很好"这类空话
- 敏感问题的回答要"诚实但不被动"——承认问题的同时展示解决思路
- 回答结构遵循"结论先行+数据支撑+行动方案"三段式
- 涉及经费的回答须精确到万元，不接受"大约""差不多"
- 涉及进度的回答须给出具体时间节点，不接受"尽快""近期"

### 步骤五：汇报技巧提醒

在材料末尾附2-3条实战汇报技巧提醒：

**常见技巧提醒库**（根据汇报类型选择）：

- 数字记忆法："今天汇报有3个关键数字请记住——99.25%准确率、12口井验证、60万追加投入"
- 开场白模板："感谢XX领导百忙之中听取汇报，我尽量在15分钟内汇报完毕。核心有三件事..."
- 过渡话术："刚才汇报了进展情况，接下来说一下我们面临的问题和建议方案"
- 收尾话术："以上就是汇报内容，请领导指示。特别希望领导就[具体事项]给个方向"
- 应对打断："领导您这个问题问得好，正好是我接下来要汇报的内容，我先回答..."
- PPT翻页提示：每页PPT讲完核心观点后，稍作停顿等领导抬头再翻页
- 时间控制：如果领导提前催促"说重点"，立即跳到"需要支持的事项"部分
- 眼神管理：汇报时60%时间看主汇报人，40%时间兼顾其他参会领导

### 步骤六：语言风格打磨

**国企汇报语言标准**：

| 维度 | 标准 | 反例 -> 正例 |
|------|------|-----------|
| 结果导向 | 先说结果，再说过程 | "经过三个月的艰苦努力我们发现..." -> "测试准确率99.25%，超过任务书指标" |
| 数字优先 | 用数字替代形容词 | "效果显著" -> "识别准确率从85%提升至99.25%" |
| 正式得体 | 符合国企行文规范 | "搞定了一个大bug" -> "修复了数据采集模块的关键缺陷" |
| 简洁有力 | 一句话说清一件事 | 长定语从句 -> 短句+数字 |
| 消除歧义 | 不用"可能""或许" | "可能能完成" -> "预计12月15日前完成" |
| 态度积极 | 展示主动作为 | "领导安排的任务我们做了" -> "我们主动推进了XX工作" |

**特殊场景用语**：

- 申请经费时：不说"要钱"，说"申请专项经费支持"；不说"太贵了"，说"经充分论证和市场比价"
- 汇报问题时：不说"出了问题"，说"在执行过程中发现了XX情况"；不说"搞不定"，说"需要更高层级的协调推动"
- 请求支持时：不说"请领导帮忙"，说"恳请领导在XX方面给予协调支持"

### 步骤七：输出与整合

最终输出包含三个部分：

1. **汇报正文**：根据汇报类型选择对应结构
2. **Q&A问答预案**：5-10个预判问题及回答要点
3. **汇报技巧提醒**：2-3条实战技巧

输出方式：
- 以 Markdown 格式直接输出
- 用户可复制到 Word/WPS 进行排版，或直接制作PPT

## 质量标准

- **结论先行**：每段开头即结论，论证在后。领导如果只看每段第一句话，也能了解全貌
- **数据支撑**：每个论点至少一个量化数据点。"好/差/多/少"不是数据，"99.25%/3口井/60万"才是
- **Q&A实用性**：预判问题命中率应>60%（即汇报中实际被问到的问题有60%在预案中）
- **回答可操作**：每个回答要点可直接口述，不需要现场组织语言
- **篇幅适度**：汇报正文控制在汇报时长对应的字数内（约300字/分钟），不堆砌信息
- **格式规范**：符合国企行文惯例，标题层级清晰，表格数据完整
- **敏感事项得体**：问题表述不回避但也不刺耳，解决方案紧跟问题之后

## 红线规则

1. **不编造数据**：所有数字必须有出处。领导如果追问"这个数从哪来的"，你必须能回答。编造的数据一旦被发现，信任将彻底崩塌
2. **不隐瞒坏消息**：如果有问题必须主动暴露，但呈现时附解决方案。"主动报告问题+有解决思路"=靠谱；"被领导问出问题+无准备"=失职
3. **决策请求须具体**：不写"请领导支持"，写"申请追加经费60万元，用于XX井场外场测试，详见附件测算"。模糊的请求等于没有请求
4. **不超越权限承诺**：汇报中不可代替领导做承诺（如"我们保证年底完成"），除非已获得授权。用"我们的目标是..."替代"我们保证..."
5. **不贬低兄弟单位**：即使对标分析中发现其他单位的问题，措辞须客观中性。国企系统内，今天的对手可能是明天的合作伙伴
6. **Q&A不可敷衍**：每个预判问题的回答要点必须实质性内容，不可用"我们一定努力""请领导放心"这类空话充数

## 灰色地带处理

1. **好消息和坏消息并存** -> 采用"成果->问题->方案"结构：先展示成果建立信任 -> 坦诚说明问题确保透明 -> 给出解决方案恢复信心
2. **领导可能不同意你的方案** -> 在材料中准备充分的对比数据和论证，用事实说话。准备一个降级方案："如果方案A暂时不具备条件，建议先实施方案B作为过渡"
3. **经费申请可能被砍** -> 准备三档预算：理想版（全额）、基础版（80%）、最低版（60%），说明每档对应的工作范围和成果差异
4. **上次汇报的承诺未兑现** -> 主动说明原因和补救措施，不要等领导追问。格式："上次汇报中我们承诺XX，目前进展是XX，与原计划偏差XX，原因是XX，已采取措施XX"
5. **多个领导同时在场且关注点不同** -> 在材料中为不同领导关注的领域分别准备章节，汇报时根据主汇报人的反应灵活调整重点
6. **领导临时要求提前汇报** -> 准备一个"5分钟精简版"——只讲核心摘要+需要支持的事项，其余留作书面材料

## 输入不足处理

- 仅提供汇报主题时：输出基础框架，标注"信息有限，建议补充核心内容和决策请求后获得更完整的汇报材料"
- 缺少关键信息时：主动向用户追问最重要的 2-3 个数据点（如汇报场景、关键成果、需决策事项）
- 绝不编造数据、案例或政策信息——无法验证的信息标注[需确认]
- **快速模式**：用户提供完整信息 -> 直接输出完整汇报材料+Q&A预案
- **引导模式**：用户仅说"帮我准备汇报" -> 先追问场景、对象、核心要点，再结构化输出

## Agent 工具增强

- **WebSearch**：搜索行业政策动态、技术发展趋势、同类项目案例，为汇报材料提供外部论据支撑
- **文件处理**：支持读取用户上传的项目报告、财务报表、技术方案PPT、历史汇报材料等，快速提取关键信息并按汇报结构重组
- **代码执行**：费用测算、进度统计、对比分析、趋势预测等使用Python确保精度
- **图像识别**：可解读用户上传的系统截图、设备照片、数据图表，提取关键数据点用于汇报材料
